## Commands

```powershell
$g = ".\Godot Engine Latest\Godot_v4.7.2-stable_win64_console.exe"

# Import / validate (run after adding assets)
& $g --headless --editor --quit --path "."

# Run the game (windowed)
& ".\Godot Engine Latest\Godot_v4.7.2-stable_win64.exe" --path "."

# Open the editor GUI  (NOTE: -e is required; --path alone RUNS the game)
& ".\Godot Engine Latest\Godot_v4.7.2-stable_win64.exe" -e --path "."

# Smoke run (headless, N frames)
& $g --headless --path "." --quit-after 400

# All 29 test suites (skip the test_env.gd helper - it is not a suite)
Get-ChildItem tests/test_*.gd | ForEach-Object {
  $n = $_.BaseName
  $o = & $g --headless --path "." --script "res://tests/$n.gd" 2>&1
  "{0,-20} EXIT={1} PASS={2}" -f $n, $LASTEXITCODE, ($o | Select-String '^PASS ').Count
}
```

Tests are `extends SceneTree` scripts run with `--script`. They must all exit 0.
Current state: **41 suites, 1995 assertions, 0 failures.** CI runs the same set on every push
(`.github/workflows/tests.yml`).

**A fresh clone cannot run the suites until assets are imported.** No `.godot/` cache means no
imported WAV/glTF/PNG, and suites that load them fail with `Cannot open file 'res://.godot/imported/...'`.
Run `& $g --headless --path "." --import` once after cloning (CI does exactly this).

Each suite redirects the save file via `tests/test_env.gd`, so runs never touch the
player's real save. `SaveSystem` resolves its path from `SHROOMLANDS_SAVE_PATH` or
`--save-path=<path>`, defaulting to `user://player_save.json`.

Autoloads: `Lore`, `EventBus`, `Game`, `SaveSystem`, `Network`, `Audio` (+ Godot AI's `_mcp_game_helper`,
editor-only and stripped from exports). `Audio` owns the Master/Music/SFX busses
(`default_bus_layout.tres`), a pooled SFX player set and the looping ambient bed; its WAV cues are
generated by `tools/generate_audio.py` and are byte-identical on every run.

## Rules that matter

- **Never trust an OS screenshot on this machine.** Windows runs at **150 % DPI scaling**, so a
  Win32 capture is a top-left *crop* of the real frame and will show the player in the corner or
  missing. Use `tests/capture_frame.gd` (in-engine viewport capture, windowed run).
- **Items are dictionary-defined** in `Lore.gd` and referenced by `StringName` id. Do not create
  hundreds of `.tres` item files.
- **Inventory** = 48 slots (6x8) of `{id, count}`, stacks of 64; hotbar = first 8 slots.
- **Physics layers:** 1 = world, 2 = decoration (ignored by the camera spring arm), 3 = harvestable
  mushrooms, 4 = plots, 5 = players, 6 (16) = enemies, 7 (32) = enemy hurtboxes and destructible hazards. The player's
  `AttackHitbox` queries `16 | 32`; the interact ray mask is `5` (world + harvestables) — changing
  it breaks `test_gathering`.
- **UI blocking:** `PlayerController.set_ui_blocking(true)` stops movement, camera and attack while
  a panel or text field is open. Build mode uses a separate flag so the player can still walk.
- **Multiplayer authority:** each peer owns its transform and vitals; the server relays. Enemy
  damage to a remote player is routed to the owner's body (`apply_damage_rpc`). Player, gold,
  inventory and discoveries are *reported*, not validated — there is no anti-cheat.
- **One transport per server instance.** `--transport=enet` (UDP, desktop) or
  `--transport=websocket` (TCP, browsers + desktop). Mixed sessions are unsupported.
- **Exports:** use `tools/export_all.ps1`, not raw `--export-release`. It strips the editor-only
  plugin setting and the MCP autoload for the duration of the export, then restores them.

## Animation: rigged player, procedural enemy

- **Player** uses `assets/models/player_rigged.gltf` — a 20-bone Blockbench humanoid rig with six
  keyframed clips (`idle`, `walk`, `run`, `attack`, `draw`, `holster`). `PlayerAnimator.gd` picks the
  locomotion clip from **measured position deltas** (so replicated bodies animate correctly), plays
  one-shots on `swing_seq` / `held_item` changes, and sets `LOOP_LINEAR` at runtime because the
  glTF importer brings every clip in as `LOOP_NONE`. Editable source: `assets/models/source/player_rigged.bbmodel`.
- The exporter writes **no skin** (`skins=0`): bones are plain nodes and the meshes are parented to
  them, so motion is rigid-per-segment. That is fine for box art and it means hand attachment is a
  plain node transform copy (`SwingWeapon`/`HeldItem`), not a `BoneAttachment3D`.
- **Enemy** (blightling) still uses `LimbAnimator.gd` — procedural, no rig. Do **not** add
  `LimbAnimator` back to the player: it would fight `PlayerAnimator`.
- **XP authority**: `PlayerStats.add_xp` is a no-op on a non-owner copy, and
  `Enemy._award_xp` routes a remote player's kill through `add_xp_rpc` to that body's owner
  (the server's mirror must never write XP or emit into the host HUD). A creature pays XP
  once (`_xp_paid`), so respawns are not a farm. Gathering pays a fifth of the species value.
- **Player face and hands are hand-patched in the glTF.** The eye meshes sample two atlas texels
  that were fully transparent while the material alpha-masks below 0.05 — the face rendered blank.
  Paint the texels (38/43, 76) dark (currently `#261A16`) in both the glTF's embedded PNG and
  `assets/models/player_rigged_0.png`; the `.bbmodel` textures carry the same fix. Each hand also
  has a second primitive with a thumb box (12 tris each) added directly to the glTF, so the mesh
  count stays 21 but a Blockbench re-export would drop the thumbs — re-add them (or model them in
  Blockbench) before exporting. `test_models.gd` pins 21 player / 15 blightling meshes.
- **Blightling eyes are self-lit**: `Enemy._setup_materials` gives the `eye*` meshes their own
  `_eye_material` copy (`EYE_COLOR`/`EYE_ENERGY`) instead of the shared body material, so they glow
  orange while the body flashes on hit. `test_models` checks both materials and the eye emission.

## Items, effects and first person

- **Design lives in `docs/ITEMS.md`** — 11 mushrooms (Konop … Fury), 4 rarity tiers
  (`common/rare/epic/legendary`), 5 depth layers, 11 brewed potions. `Lore.gd` carries the data;
  `MUSHROOMS[*].eat` is the raw effect, `.brew` points at a potion id + gold fee.
- **Effects** are dictionaries applied by `PlayerStats.apply_effect`: instants (`heal`,
  `heal_over_time`, `stamina`, `self_damage`, `cleanse`), `poison {damage, duration}` and
  `buff {id, duration, max_hp_flat?, max_stamina_flat?, damage_mult?, armor_mult?, vision?}`.
  Buffs **refresh, never stack**; `max_hp_flat` adjusts the maximum and reverts on expiry.
  `CombatSystem` reads `damage_mult`; incoming damage is scaled by `armor_mult`.
- **Eating** = `InventorySystem.use_slot(i)`, bound to **double-click** in the satchel;
  right-click still drops. Toxicity is applied after the effect. The **Alchemy Table is data only**
  so far — `POTIONS`/`potion_for()` resolve but there is no brewing UI yet.
- **Models**: `assets/models/mushrooms/<id>.gltf` for all 11 species.
- **Action skills** (`Lore.SKILLS`, `Game.skills`): four flat tracks — `foraging`, `alchemy`,
  `combat`, `survival` — each starts at level 1, costs `60 * level` xp per level, caps at 20, and
  is saved as `skills`. XP is awarded by doing: gather (`Game._on_mushroom_gathered`), brew
  (`AlchemyUI.brew`), kill (`Enemy._award_xp` / `PlayerStats.add_xp_rpc`), search
  (`SearchableCrate._complete`) and extract (`Game.finish_run`). Perks are read, not baked in:
  `Game.foraging_bonus()` (+1 harvest at 5/10/15), `Game.alchemy_fee()` (-1 g/level),
  `Game.combat_skill_scale()` (+2%/level in `CombatSystem.level_damage_scale`),
  `Game.survival_lamp_scale()` (`SporeLamp._ready`) and `Game.survival_search_scale()`
  (`SearchableCrate._process`). A chosen vocation adds +25% xp to its `affinity` skill. UI: the
  pause menu's Skills page and a level-up toast. Test: `test_skills.gd` (49 assertions).
- **Resources & gear**: the six `Lore.RESOURCES` drop from structure loot —
  `Lore.STRUCTURE_RESOURCES` keyed by structure kind (0 hut, 1 castle, 2 dungeon), plus
  `ancient_core` only in a layer-5 dungeon (`LayeredForest._resource_pool`). `Lore.GEAR` defines
  four slot items with recipes (`mycelium_fiber` etc. + a fee): `quiet_boots` (feet,
  `noise_mult 0.6`), `muffled_pack` (back, `search_noise_mult 0.5`), `bright_lamp` (light,
  range/energy/battery multipliers) and `mycelium_vest` (body, `armor_mult 0.85`).
  `InventorySystem.equipped_gear` is slot -> id, one item per slot, saved as `gear`; double-click a
  gear item in the satchel equips it. Effects are read at use: `PlayerStats.incoming_damage_multiplier`
  (armour), `SporeLamp._apply_gear` (beam/battery, also on `gear_changed`), `VoiceInput._emit` and
  `SporeLamp` (boots noise), `SearchableCrate._complete` (pack noise). The **Workshop**
  (`scripts/ui/WorkshopUI.gd`, `scenes/ui/workshop.tscn`) spends materials + gold and refuses
  duplicates; `Main.validate_inventory_payload` accepts gear ids. Test: `test_gear.gd` (54).
- **Weapons**: `Lore.WEAPONS` holds the starting `mycelium_club`. `InventorySystem.equipped_weapon`
  is the item id; `ensure_starting_weapon()` runs on spawn and migrates old saves. `use_slot` on a
  weapon equips/unequips (it never gets eaten), and `drop_slot` clears the equip when the last one
  leaves. `CombatSystem.current_attack_damage` uses the item (12/22) or bare hands (4/7).
  `SwingWeapon` reads the replicated `PlayerController.equipped_weapon` and shows the club only
  while equipped; `HeldItem` excludes weapons from the left hand. `validate_inventory_payload`
  accepts weapon ids, and the save adds `"weapon"` to the inventory dict. `SaveSystem` only
  runs `ensure_starting_weapon()` when that key is absent (an older save), so a dropped club
  is not handed back and an unequipped one stays unequipped; `weapon_condition` is saved too.
  Levels add 3% melee damage (`CombatSystem.level_damage_scale`). Test: `test_weapon.gd`.
- **First person is the default**: `camera_distance = 0.05` puts the view at the eyes on frame one
  (`_ready` applies the eye offset and FP state); the wheel zooms out to 8 m with exponential easing.
  Below 0.6 m (0.15 m hysteresis) the head/cap/eye meshes hide, the pitch range widens to ±85°, and
  `FpArms.gd` overrides the arm bones at `process_priority = 100` (after the rig's AnimationPlayer)
  to bring the arms and both props into frame. Known limit: the arms are the third-person block arms, and the `attack/draw/holster`
  one-shots do not move the FP arms.

## Presentation: first person, grade, ambience

- **Screen grade** (`scripts/ui/ScreenFX.gd`, `scenes/ui/screen_fx.tscn`, shader
  `assets/shaders/screen_fx.gdshader`): CanvasLayer 5 samples the frame and applies a per-biome/layer
  tint, a danger vignette + grain + chroma split. It is below the HUD (10) and reads
  `Atmosphere.danger_level()`.
- **Atmosphere** (`scripts/core/Atmosphere.gd`, a Node in `main.tscn`): every 6-14 s in the forest
  (16-30 s in town) plays `creak`/`whisper`/`drip` at -26..-18 dB; the heartbeat quickens from 1.7 s
  to 0.55 s as danger rises; `Audio.set_ambient_danger()` shifts the bed's pitch. Danger is the max
  of `1 - hp_ratio` and proximity to any `enemy` within 20 m.
- The four cues are generated by `tools/generate_audio.py` like every other sound.
- Test: `test_atmosphere.gd` (19 assertions).

## The layered forest

- **Layout is data**: `scripts/world/ForestRun.gd` builds a deterministic graph from
  `(layer, seed)` — a winding spine from the entry to the exit plus `2 + layer` side branches,
  so every run has forks and dead ends. `hazard_ids` and `structure_id` are overlays on the
  structural kinds, so a junction can carry a bloom and still be a junction. `test_forest_run.gd`
  checks determinism, connectivity and the layer guarantees without a scene tree.
- **Dressing** is `scripts/world/LayeredForest.gd` (`scenes/world/layered_forest.tscn`): ground,
  path strips, species-correct `MushroomNode`s from `Lore.mushrooms_in_layer`, one `SporeBloom`
  per hazard id, and the gates. The structure follows the depth: hut on 1, castle on 2-3,
  dungeon on 4-5 (`ForestRun.structure_kind`), each with a chest and three crates. Depth has no
  level gate or level range: a party unlocks the next layer by walking it (the descent gate at the
  exit), as the design asks. Walls,
  towers, dungeon pillars and hut posts are `StaticBody3D` solids on layer 1, so a player or enemy
  cannot walk through them; `test_layered_forest` counts them. `Game.forest_layer` (1-5,
  0 outside the forest) selects the layer, so one scene serves all five.
- **Travel**: the town's `DescentGate` sets `target_layer = 1`; the forest's `DescentGate`
  targets `layer + 1`; `ReturnGate` targets town. `AreaGate.target_layer` writes
  `Game.forest_layer` before `Main.enter_area`, which keeps it only for the forest path and
  resets it to 0 elsewhere. Layer 5 has no descent gate.
- **Danger scales with depth**: `Main._make_enemy` multiplies max HP, bite damage and XP by
  `Game.forest_layer` (base stats in town and the Verdant Bloom). Hazards are only placed two
  cells (16 m+) from the entry, so the spawn clearing is safe.
- **Known gap**: the save file stores the player's coordinates but not the active area, so a
  save taken in the forest restores those coordinates while the session starts in town.

## Run goal, death stakes and summary

- **Quota**: any forest departure calls `Game.finish_run()` first — including descending to
  another layer, which used to skip the summary and the 50% quota bonus — then
  `Game.start_run(layer)` opens the new run. `Game.start_run(layer)` sets `run_gold = 0` and
  `run_quota = 40 + 20*layer`. `Game.add_run_gold()` (chests/crates) and
  `EventBus.mushroom_gathered` (at `Lore.mushroom_value`) feed `run_gold`; the HUD
  `QuotaLabel` shows `LOOT X / Y g`.
- **Death stakes**: `PlayerStats.die()` in a forest calls `_drop_run_loot()`: half of
  every carried stack is removed (per species, rounded **up**, so a lone item is never free)
  and `Game.note_run_death()` records it. The purse and equipped weapon survive.
- **Summary**: leaving a forest for town calls `Game.finish_run()`, which stores
  `last_run` and emits `EventBus.run_finished`; meeting the quota pays a `quota/2`
  bonus. `RunSummary` (CanvasLayer in `main.tscn`) sets the player's `ui_blocking` and
  shows layer, loot/quota, bonus, mushrooms, deaths and time; Continue closes it.
- Test: `test_run_goal.gd` (37 assertions).

## Voice and the leader

- **Voice hearing** (`scripts/player/VoiceInput.gd`, a child of `Player`): `V` opens a private
  "Microphone" bus (captured, muted to -80 dB so it is never echoed) and measures RMS. Loudness
  above 0.06 emits `EventBus.disturbance_emitted` every 0.4 s with a 5-24 m radius, which every
  `Enemy` already investigates — so talking or screaming pulls creatures from outside aggro.
  Off by default for privacy; toasts report on/off and a missing mic. The HUD `MicLabel` shows
  `MIC off (V)` or a six-bar level. `push_voice(0..1)` is the same path the mic uses and is what
  the headless suite drives.
- **The leader** (`scripts/core/Party.gd`, autoload): `leader_id` defaults to 1 (the host, and
  offline the local peer). Helpers: `is_leader(player)`, `leader_node()`, `local_is_leader()`,
  and `leader_is_near(pos, radius)` which treats a dead leader as absent.
- **Only the leader carries the lamp**: `SporeLamp.toggle()` refuses for anyone else, and
  `Party.leader_changed` turns a passed lamp off and disables its drain/beam.
- **No way back without them**: the forest `ReturnGate` and the layer-5 `ExitGate` set
  `AreaGate.requires_leader = true`; `interact` refuses with a toast unless a living leader is
  within 14 m. Descent gates deliberately do not require it.
- **Handoff and party HUD**: `L` (`pass_lamp`) on `PartyActions` calls
  `Party.pass_to_nearest(player, 8 m)`. Only the current leader may pass it (the server checks
  the RPC sender), and the HUD `PartyLabel` marks the leader with `[LAMP]`.
- **Replication**: `VoiceInput`, `SporeLamp` and `SearchableCrate` call
  `Network.report_disturbance()`; offline/server applies it locally, a client forwards it to the
  server, so the server's creatures hear every peer. `Party.set_leader()` uses `request_leader` /
  `apply_leader` RPCs and `Main` syncs the leader to each peer on connect.
- **Area travel is server-authoritative**: a client asks the server, which validates the path and
  the forest leader rule, swaps, and broadcasts `apply_area`; every peer rebuilds the deterministic
  area. Offline the local peer applies directly.
- Tests: `test_voice_and_leader.gd` (21 assertions) and the two-process
  `tests/run_horror_net_test.sh` (host + client over ENet).
- **Server-authoritative run props**: a crate search sends `request_open`; the server verifies
  the sender is within `cancel_range + 1`, opens it, broadcasts `apply_opened` and pays the
  owner through `Main.send_loot` / `grant_loot`. The Blight spawns through a
  `MultiplayerSpawner` whose `_make_blight` runs identically on every peer.

## Horror search (the YAPYAP / Lethal Company pass)

The lower forest follows the co-op-horror shape: it is dark, you search for loot,
noise and light pull creatures, and you extract through the gate.

- **Run clock**: the server owns `LayeredForest.time_left` and decrements it in
  `_physics_process`; the forest scene carries a `MultiplayerSynchronizer` (`RunSync`, property
  `.:time_left`) so clients see the countdown. Clients drive their own HUD from the replicated
  value and call `_announce_blight()` when it reaches zero, so a late joiner gets the countdown
  and the "Blight has found you" toast. Offline has no peer object and still ticks — the old
  `multiplayer_peer == null` guard froze the clock in single player.
- **Night layers**: `LayeredForest.is_dark` is true on layers 3-5. The sun drops to 0.10,
  ambient to 0.26/0.21/0.16, the sky background dims to 10% and the fog thickens. Layers 1-2
  stay lit.
- **Spore-lamp** (`scripts/player/SporeLamp.gd`, a `SpotLight3D` on the player, not the camera
  pivot): `F` toggles it. 90 s battery, 1/s drain, 0.35/s recharge while off, stutter under 20%.
  The chest-height beam points forward/down and reaches 22 m. While lit it emits
  `EventBus.disturbance_emitted(pos, 16 m)` every 1.2 s; the switch itself emits 5 m.
- **Searchable crates** (`scripts/world/SearchableCrate.gd`, three per structure): interact and
  stay within 4 m for 1.2 s. Pays 1 layer species + `5 + 3*layer` gold, emits a 14 m
  disturbance, and never refills. The `LootChest` remains the larger, instant reward.
- **Extraction pressure**: `LayeredForest.run_seconds` (180 s) starts on entry and drives
  `EventBus.run_timer_changed` (HUD `RunLabel`; -1 hides it). At zero `expire_run()` spawns one
  `Blight` from `enemy.tscn`: 100k HP, 400 m aggro, 6.4 m/s, 90 bite damage, no respawn — the
  YAPYAP ghost. It is released once; leaving the area frees it with the world.
- **Creatures investigate**: every `Enemy` listens on `disturbance_emitted`; if it is inside
  the radius it walks to the point for 4 s (`is_investigating()`), even when the player is
  outside the 12 m aggro range. Using the lamp or searching a crate is therefore a real risk.
- Test: `test_horror_search.gd` (33 assertions).

Not yet: an extraction timer / inescapable ghost, dropping carried loot on death, and a
dedicated sound-only stalker.

## Hazards

- **Spore Bloom** (`scenes/world/spore_bloom.tscn`, `scripts/world/SporeBloom.gd`,
  `assets/models/hazards/spore_bloom.gltf`): a fat veined mushroom, never loot.
  - Arms when a living player is within 2.5 m (flat distance), swells for 0.6 s, then bursts
    into a 3 m cloud for 6 s. The cloud ticks 3 damage every 0.75 s and stops the moment the
    player leaves the radius.
  - 20 HP: two light swings destroy it. A destroyed bloom never bursts and drops nothing.
  - Physics layer 32 + group `hazard`. `CombatSystem._damageable_from` accepts `enemy` **and**
    `hazard`, so a swing reaches it; the player's movement mask does not, so it never blocks a
    path (unlike a harvestable mushroom, which sits on layer 4).
  - Authority mirrors `Enemy`: the server runs the trigger and the ticks, damages its own
    player directly and routes a remote player through `Stats.apply_damage_rpc`.
    `state` and `dead` replicate through a `MultiplayerSynchronizer` (the setter drives the
    visuals), so a client sees the swell and the cloud without running the trigger.
  - Three fixed placements in `verdant_bloom.tscn`; the layered forest will add more.

## Areas and the town hub

- **Area switching**: `Main.enter_area(path)` frees the current `World`, instances the new scene,
  moves the local player to that area's `PlayerSpawn`, and emits `EventBus.area_changed`. UI layers
  are siblings of `World`, so HUD/panels survive the swap. Each area scene exports `display_name`
  (`Town.gd` = "Mycoria", `VerdantBloom.gd` = "Verdant Bloom") which the HUD caption follows.
  **Area travel is server-authoritative**: a client asks the server, which validates the path and,
  when leaving a forest, that a living leader is within 14 m of the return gate, then broadcasts
  `apply_area`. Every peer rebuilds the deterministic area from the same layer. The save stores
  `area` and `forest_layer`, and `_restore_offline_save` swaps there before restoring the saved
  position (`test_area_persistence.gd`).
- **Town** (`scenes/world/town.tscn`, the default world in `main.tscn`): walled 60 m settlement with
  the plot row just outside the north gate. Stations are generic `station.tscn` + `Station.gd`
  instances (Shop, Alchemy Table, Repair Bench, Plot Board); `area_gate.tscn` handles Town↔Verdant
  Bloom.
- **Stations**: Shop buys/sells (`Lore.mushroom_value` 5/20/60/150, `Lore.potion_price` = fee × 3);
  Workshop crafts gear from structure materials + fee; Alchemy brews mushroom + fee into a potion;
  Repair Bench restores `weapon_condition`
  (0-100, −1 per swing, damage halved at 0) for **2 g per point**; Plot Board is read-only.
- **Gated potions**: `armour_patch` (needs equipment), `nighteye_draught` (vision buff not read
  by the camera) and `spore_bomb` (no throwables) are listed but their buttons are disabled and
  the operations refuse, because those systems do not exist yet. Do not "fix" this by making
  them silently charge gold.

### Mushroom models — headless Blender (Linux/CI)

The eleven species models now come from `tools/blender/mushroom_forge.py`, which runs
without a GUI or GPU and writes a self-contained `assets/models/mushrooms/<id>.gltf`.

## MCP tooling live in this workspace

- `godot-ai` (47 tools) — drives the **running** Godot editor: scenes, nodes, scripts, playtests,
  screenshots, input simulation, LSP diagnostics. Needs the editor open on this project.
- `blockbench` (71 tools) — 3D authoring, texturing, rigging, animation, glTF export.

Known limitation: in multiplayer, `Game.get_local_player()` can fall back to a client body on a
dedicated server, so server logs show extra `INV_RECV peer=1` lines. Harmless, but do not build
server-side logic that assumes it returns the host's own body.
